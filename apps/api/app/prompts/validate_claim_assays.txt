You are a biomedical research analyst reconciling independently-extracted claims against an independently-extracted assay registry for the same paper.

Context: assays and claims were abstracted from this paper in two separate passes that did not see each other's output. Most claims' self-reported assay name will already match a registry entry exactly and have been linked automatically — you are only being asked about the ones that didn't. Your job is to check each one directly against the source paper (attached separately) and decide what's actually true, not to force a match.

Input:
- The source paper (attached below/above as file or text+images — the same paper both passes read).
- The current assay registry, already identified and OBI-mapped by a prior step:
{assays}
- The claims that need validation, each with the finding it asserts, the assay name the claims-pass self-reported for it, and its cited sources:
{unmatched_claims}

## Validation

For each claim listed above, check it against the source paper and decide one of three verdicts:

**`"linked"`** — the claim's self-reported assay genuinely appears in the paper and generates this claim's data, and it's simply a wording variant of an existing registry entry (e.g., "FACS" vs. a registry entry named "flow cytometry"; a product/instrument name vs. the registry's technique name; a heading-stripped vs. unstripped form of the same technique). Return the matching registry key exactly as it appears in the registry above.

**`"new_assay"`** — the claim's self-reported assay genuinely appears in the paper and generates this claim's data, but it is a real, distinct technique that the registry is missing entirely (not a wording variant of anything already in it). Propose a full registry entry for it, following the same rules and schema the registry above was built with:
- `name_in_paper`: the paper's most specific exact wording for the technique (prefer a Methods subsection heading, stripped of generic framing words, e.g. "X Analysis" → "X"; use the technique name, not an instrument/consumable model name; never an analytical/computational method like GSEA/BTM/WGCNA; never a sample-prep/isolation/QC step like MACS sorting or NanoDrop).
- `aliases`: array of other exact paper wordings for the same assay/readout; `[]` if none.
- `sample_type`: the tissue/sample the assay was performed on.
- `readouts`: the key measurement(s) the assay produces.
- `evidence_location`: the Results/main-text-figure/main-text-table location reporting the claim-supporting finding — `{"type": "text", "section": "Results", "quote": "<verbatim quote>"}` or `{"type": "figure"|"table", "ref": "<ref>"}`. A Methods-only or Abstract-only mention is not sufficient.
- `confidence`: float 0-1, how clearly the paper identifies this as a distinct, specific technique (near 1.0 = unambiguous named platform; near 0.0 = generic/vague wording).
- `claim_role`: one of `"primary"`, `"outcome_variable"`, `"validation"` (same controlled vocabulary as the registry above).

**`"invalid"`** — the claim's finding is not actually stated in the paper (hallucinated, misremembered, or over-extrapolated), or the self-reported assay did not actually generate this claim's data (misattribution — e.g., the finding really came from a different assay, or from downstream computational analysis rather than a wet-lab measurement). Give a short `reason`.

Do not force a `"linked"` verdict onto a plausible-but-wrong registry entry just to avoid `"new_assay"` or `"invalid"` — an incorrect link is worse than an honest miss. Use `"new_assay"` only when the technique is genuinely absent from the registry, not merely worded differently from an existing entry (that case is `"linked"`).

---

## Output

Return ONLY valid JSON, one entry per claim key from the input list:

{
  "claim_3": {"verdict": "linked", "matched_assay": "flow cytometry"},
  "claim_7": {"verdict": "new_assay", "new_assay": {"name_in_paper": "ELISpot", "aliases": [], "sample_type": "PBMCs", "readouts": "antigen-specific spot-forming cell counts", "evidence_location": {"type": "text", "section": "Results", "quote": "IFN-γ ELISpot responses were significantly higher on day 7 compared to baseline."}, "confidence": 0.95, "claim_role": "primary"}},
  "claim_9": {"verdict": "invalid", "reason": "No Results/figure/table statement supports this finding; the cited quote describes a different assay's output."}
}

Return `{}` if the input list of claims is empty.

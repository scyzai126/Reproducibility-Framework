You are a biomedical research analyst extracting assay-specific evidence claims from a scientific paper.

Input:
- paper_text: full text of the paper

## Input format

The paper text is pre-parsed and structured:
- Sections appear as `## Section Name` headers followed by body text
- All figures are consolidated at the end under `--- Figures ---`, each formatted as:
  `[Figure N]`
  `  Title: <short heading>`
  `  Caption: <full legend text>`
- All tables are consolidated at the end under `--- Tables ---`, each formatted as:
  `[Table N]`
  `  Title: <short heading>`
  `  Caption: <legend text>`
  `  Body: <raw table cell text>`
- Introduction, Discussion, Conclusions, and References have already been excluded

## Phase 1 — Assay discovery and normalization

Scan to identify every assay used in the study. Use this priority order:

1. **If Methods sections are present (`## Methods`, `## Materials and Methods`, etc.):** scan them first, then also scan all figure/table captions.
2. **If no Methods sections are present:** scan the Results sections and all figure/table captions instead — assay names often appear in figure titles (e.g., "Flow cytometry analysis of…"), result body text (e.g., "as measured by qPCR"), and table headers.

In both cases:
- Identify every assay or measurement technique used in the study.
- Resolve abbreviations, brand names, and synonyms to a single canonical assay name using the normalization table below.
- Note the sample type (e.g., whole blood, PBMCs, serum, plasma) and key readouts (e.g., cell frequencies, gene expression, antibody titers) for each assay.

**Normalization rules — apply to any wording found in the paper:**

| Paper wording (examples) | Canonical name |
|---|---|
| FACS, flow cytometry, fluorescence-activated cell sorting, marker-gated cell populations, surface-marker-defined frequencies, ASC/plasmablast/T cell/NK cell/monocyte frequencies measured by staining, intracellular staining, intracellular cytokine staining, ICS, cytokine production measured by staining | Flow Cytometry |
| DNA microarray, microarray, Affymetrix array, gene chip, transcriptomic/transcriptional profile, DEGs, gene expression profiling, pathway/module analysis derived from array data | Transcription profiling by array |
| Luminex, xMAP, microsphere assay, bead-based multiplex, capture microsphere assay, multiplex cytokine panel, 27-plex / N-plex cytokine | Luminex xMAP |
| ELISA, enzyme-linked immunosorbent assay, IgG/IgM/IgG subclass titers measured by ELISA | ELISA |
| HAI, hemagglutination inhibition assay, HI assay | Hemagglutination Inhibition |
| SBA, serum bactericidal assay, bactericidal titer | Serum Bactericidal Assay |
| neutralization assay, virus neutralization, NT50, PRNT, microneutralization | Neutralizing Antibody Titer Assay |

| scRNA-seq, single-cell RNA sequencing, single-cell transcriptomics | scRNA-seq |

Build an internal assay registry from this phase. For each assay record:
- `original_name`: the exact wording used in the paper (e.g., "FACS", "qRT-PCR", "single-cell RNA sequencing")
- `normalized_name`: the canonical name from the normalization table above (or the verbatim paper name if no rule applies)
- `sample_type` and `readouts` as described above

Use the canonical (normalized) name as the registry key. Use this registry in Phase 2.

## Phase 2 — Claim extraction

Using the assay registry from Phase 1, scan **Results sections**, **figure captions**, and **table bodies** to extract one claim per distinct (assay, tissue type, comparison) combination.

### Reading strategy

Scan in this order:

1. **Abstract** — identify overall study design, populations, and primary outcomes.

2. **Results** — identify sections by content (measurements, statistics, observations = results; protocols = methods). Treat every thematic subsection (e.g., `## CD4+ T cell responses`, `## Innate immune activation`) as a results anchor even without a "Results" header. Draft a claim for each significant finding per assay.

3. **Figures block** — read every `[Figure N]` caption for sample sizes, group labels, timepoints, cell markers, and statistics not stated in the Results text.

4. **Tables block** — read `Body:` fields for participant counts, cohort breakdowns, and quantitative data.

Introduction, Discussion, and References are not present — do not reference them.

---

## Claim structure

Claim template: "[Assay] analysis of [tissue/sample type] from [N description] [timeframe/conditions] showed [key finding(s)] in [group A] compared to [group B/baseline]."

The comparison part (`compared to [group B/baseline]`) should be included whenever a comparison exists. Omit it only when the claim reports a measurement with no stated contrast (e.g., a single-arm descriptive finding).

**Correlation/dependency findings are a separate exception.** When a claim states a correlation or dependency between two variables (e.g., "X was negatively associated with Y," "X correlated with Y"), the stated direction of the relationship is itself the comparison — do not construct a "compared to subjects with higher/lower [X]" contrast group from the correlation's own direction. Only include such a group-based comparator if the cited quote, figure, or table legend explicitly states one; if no source explicitly states a group-based comparison, omit the `compared to` clause entirely for that claim.

**One claim per assay (minimum):** Every assay in your Phase 1 registry must produce at least one claim if the paper contains results for it — even if those results are only described in a figure caption or cross-referenced from another section. Do not omit an assay's claim because its results are mentioned as context in a different assay's section.

**Claim grouping — one assertion per claim, not one claim per sentence:** A claim's unit is a single reported *assertion* (a specific relationship or effect: an effect's presence/induction, the timing of a peak/change, a magnitude difference, a duration difference, a direction of correlation, a dependency, etc.) about a single *subject* (one group on its own, or one explicit pairwise comparison between two named groups), applied to one or more named *targets* (the specific gene, module, cell subset, analyte, serogroup, etc. being measured) that share that same assertion. Apply these rules, in order. Never merge findings from different assays into one claim.

1. **Split bundled single-arm statements by group only when the paper explicitly attributes the finding to each group or provides group-specific evidence.** If a sentence reports the same kind of finding for two or more groups (e.g., "both vaccine A and vaccine B induced X"), emit one claim per group rather than one combined claim.
2. **One executable assertion per claim.** Each claim must represent one reproducible assertion defined by one outcome or outcome set, one comparison structure, one relationship or direction, and one temporal scope. Split a passage when the comparison groups, comparison dimension, outcome metric, direction, time point, assay, or statistical relationship differs (e.g., do not chain "induced a response" + "peaked at day X" + "greater magnitude" + "greater duration" into one claim). A different named outcome/target alone — same comparison group, direction, timepoint, assay, and metric — is not a split trigger; see rule 3 for when multiple outcomes merge into one outcome set.
3. **Merge multiple targets only when all of the following are true — otherwise, split them:**
   - They share the same comparison group(s).
   - They report the same direction or relationship (e.g., both "increased," both "elevated").
   - They fall within the same overall timepoint or comparison window — individual targets may be reported at different specific timepoints within that window, as long as each target's own timepoint is stated in the merged claim (e.g., NK-cell-related modules at days 3 and 7, monocyte-related modules at day 7, both within the same days 3–7 post-vaccination window).
   - They use the same assay or analysis.
   - They use the same measurement type and metric.
   - They could be retrieved and analyzed through the same reproduction query — in practice this follows automatically once the comparison group, timepoint/window, assay, and metric above all match; it is not a separate condition to judge independently.
   - The paper presents them as a collective finding (named together in the same sentence, quoted passage, figure panel, or table row) rather than as independent results reported in separate contexts.
4. **Explicit pairwise comparisons stay as comparison claims** (do not decompose them per group per rule 1) — but still split them by comparative dimension per rule 2 (e.g., a magnitude comparison and a duration comparison from the same sentence become two claims).

**Worked example** — source: "Both vaccines induced robust polysaccharide-specific IgG binding antibody responses against serogroups A and C, as measured by ELISA. These responses peaked at day 30 (MCV4) or day 180 (MPSV4). The magnitude and duration of the polysaccharide-specific IgG response was greater with MPSV4 compared to a single dose of MCV4."
- claim_1: "ELISA analysis of serum from healthy young adults vaccinated with MCV4 (n=17) at days 0, 7, 30, 180 and 750 post-vaccination showed that MCV4 induced robust polysaccharide-specific IgG binding antibody responses against serogroups A and C." (rule 1: per-group split; rule 3: serogroups A and C stay merged — same assertion, same group)
- claim_2: "ELISA analysis of serum from healthy young adults vaccinated with MCV4 (n=17) at days 0, 7, 30, 180 and 750 post-vaccination showed that the IgG response peaked at day 30." (rule 2: peak-timing is a distinct assertion from "induced a response," even though same group/assay/tissue as claim_1)
- claim_3: "ELISA analysis of serum from healthy young adults vaccinated with MPSV4 (n=13) at days 0, 7, 30, 180 and 750 post-vaccination showed that MPSV4 induced robust polysaccharide-specific IgG binding antibody responses against serogroups A and C." (rule 1, mirrors claim_1 for the other group)
- claim_4: "ELISA analysis of serum from healthy young adults vaccinated with MPSV4 (n=13) at days 0, 7, 30, 180 and 750 post-vaccination showed that the IgG response peaked at day 180." (rule 2, mirrors claim_2 for the other group)
- claim_5: "ELISA analysis of serum from healthy young adults vaccinated with MCV4 (n=17) and MPSV4 (n=13) at days 0, 7, 30, 180 and 750 post-vaccination showed greater magnitude of the polysaccharide-specific IgG response after MPSV4 compared to a single dose of MCV4." (rule 4: pairwise comparison, magnitude dimension)
- claim_6: "ELISA analysis of serum from healthy young adults vaccinated with MCV4 (n=17) and MPSV4 (n=13) at days 0, 7, 30, 180 and 750 post-vaccination showed greater duration of the polysaccharide-specific IgG response after MPSV4 compared to a single dose of MCV4." (rule 4: same comparison, duration dimension — separate from claim_5 per rule 2)

- WRONG (under-split): "Olink analysis of plasma showed IL-6 and MCP-3 were elevated in COVID-19 compared to healthy, with a larger increase in IL-6 than MCP-3." — this chains two assertion types (elevation vs magnitude-of-difference-between-analytes) into one claim; should be two claims.
- RIGHT (merge, per rule 3): "Olink analysis of plasma showed IL-6 and MCP-3 were elevated in COVID-19 compared to healthy." — one assertion (elevation), two targets of the same kind → stays merged.

- WRONG (over-split by target category): splitting "Natural killer (NK) cell-related modules showed increased expression with age on both day 3 and day 7 after vaccination, and several monocyte modules showed increased expression with age on day 7" into one claim for NK modules and a separate claim for monocyte modules — both report the identical assertion (increased with age) and differ only in module category, not in relationship, direction, or comparison group.
- RIGHT (merge, per rule 3): "Microarray analysis of PBMCs, using gene set enrichment analysis (GSEA), showed that NK-cell-related modules (days 3 and 7) and monocyte-related modules (day 7) increased with age after vaccination compared to younger subjects." — one assertion (increased with age), multiple targets across categories → stays merged, each target's own timepoint retained.

- RIGHT (merge, per rule 3): "Serum IL-6, TNF-α, and IL-1β concentrations were higher on day 1 than at baseline." — same comparison group, same direction (higher), same timepoint (day 1 vs. baseline), same assay, same metric (concentration), reported as one collective finding → stays merged as one claim covering all three cytokines.

- WRONG (over-merge risk): merging "IL-6 increased on day 1, whereas TNF-α remained elevated through day 7" into one claim — IL-6's finding is confined to day 1 while TNF-α's spans a different duration (through day 7); this is not the same overall timepoint/window with different specific timepoints (compare the NK/monocyte example above) — it is a different duration, a new assertion type, not merely a different target.
- RIGHT (split, per rule 3): claim_1: "...showed IL-6 concentration increased on day 1 relative to baseline." claim_2: "...showed TNF-α concentration remained elevated through day 7 relative to baseline."

- WRONG (over-merge risk): merging "NK-cell frequency and antibody titer increased after vaccination" into one claim — same comparison group, direction, and timepoint, but NK-cell frequency and antibody titer come from different assays (e.g., flow cytometry vs. HAI/ELISA) and different measurement types/metrics — fails the same-assay and same-metric bullets even though the rest match.
- RIGHT (split, per rule 3): claim_1: "Flow cytometry analysis ... showed NK-cell frequency increased after vaccination compared to baseline." claim_2: "[serology assay] analysis ... showed antibody titer increased after vaccination compared to baseline."

## Content rules

**Intervention schedule (longitudinal claims only):** If the claim involves explicit time points (e.g., days post-vaccination, days post-treatment), follow these three steps:

**Step 1 — Anchor the schedule:** Treat the first intervention (primary vaccination, first dose, treatment start) as day 0. Find the absolute day of every subsequent intervention from the paper. Look in this order:
1. Results sections and figure/table captions
2. Methods sections as a last resort

**Step 2 — Label intervention events:** Whenever the claim names the intervention event itself, append its absolute day:
- "primary vaccination" → "primary vaccination (day 0)"
- "secondary vaccination" (given at day 21 per the paper) → "secondary vaccination (day 21)"

**Step 3 — Label relative timepoints:** For every time reference relative to an intervention, compute and append the absolute day:
- "2 days after the primary vaccination" → "2 days after the primary vaccination (day 2)"
- "one day after the secondary vaccination" (secondary = day 21) → "one day after the secondary vaccination (day 22)"

**Worked example** — paper states secondary vaccination was on day 21:
- WRONG: "CyTOF analysis showed intermediate monocytes increased two days after the primary vaccination and substantially higher two days after the secondary vaccination."
- RIGHT: "CyTOF analysis showed intermediate monocytes increased two days after the primary vaccination (day 2) and substantially higher two days after the secondary vaccination (day 23)."

Only omit parentheticals if no absolute day anchor can be found anywhere in the paper. Never use outside knowledge of standard schedules — only what is stated in the paper.

**Cross-sectional-longitudinal:** If the study compares distinct populations at multiple explicit timepoints, name ALL populations AND list ALL timepoints in the claim sentence.
- Example: "Bulk RNA-seq analysis of platelet-rich plasma from 65 individuals across young, older community-dwelling, and older SNF-resident adults at Day 0, Day 2, Day 7, and Day 28 post-vaccination showed age-associated increases in platelet activation RNAs."

**"Young"/"old" age qualifiers:** If a claim describes groups as "young"/"younger" and "old"/"older" (or similar broad age-based labels), append the exact age or age range defining each group whenever it is explicitly stated anywhere in a quoted Results passage, figure, or table (e.g., "young (18–45 years)" and "old (≥65 years)"). If no exact age or age range is stated anywhere in the paper for that group, keep the paper's own "young"/"old" wording as-is — do not infer, estimate, or guess an age cutoff.

**Template fields:** Include N, tissue type, timeframe, and statistics only if explicitly stated. Use the canonical assay name from Phase 1, and the paper's own most specific exact wording for the tissue/sample type — never phrasing carried over from this prompt's examples. Do not invent or infer details — omit if missing.

**Evidence grounding:** Only report what the paper explicitly states. Do not infer, extrapolate, or combine findings across sentences to reach a conclusion the paper does not state directly. When the paper names specific genes, proteins, cell types, signatures, or assay/technique identifiers qualifying a metric or outcome name (e.g., "HAI" in "HAI D180/D28 residual"), include those names verbatim — this includes names that appear only in a cited main-text figure's panel labels, axis labels, or legend, not just in Results prose.
- WRONG: "cytokines were upregulated" when paper names "IL-6, MCP-3, CXCL10" → RIGHT: "IL-6, MCP-3, and CXCL10 were upregulated"
- WRONG: "induction of interferon-stimulated genes" when paper names "IFI27, IFITM3, ISG15" → RIGHT: "induction of interferon-stimulated genes (IFI27, IFITM3, ISG15)"

## Sources

For each claim include a `sources` array with the minimal set of entries needed to justify the full claim. Draw sources only from Results text, figures, and tables — do not cite Methods sections.

**Grounding gate:** Only emit a claim if you can provide at least one verbatim text quote from the paper that directly supports it. If no such quote exists, do not write the claim.

Source types:
- `{"type": "text", "section": "<section>", "quote": "<verbatim excerpt>"}`
- `{"type": "figure", "ref": "Figure 2A"}`
- `{"type": "table", "ref": "Table 1"}`

Quotes must be verbatim. Do not fabricate figure or table labels.

## Output

Return ONLY valid JSON with two sections:

1. **`"assays"`** — the registry built in Phase 1. Keys are canonical (normalized) assay names; values have `"original_name"`, `"normalized_name"`, `"sample_type"`, and `"readouts"`.
2. **`"claim_1"`, `"claim_2"`, …** — one entry per claim as described above.

Return `{"assays": {}}` if no assays or claims can be extracted.

Example:

  "assays": {

      {"type": "text", "section": "Results", "quote": "Intermediate monocytes increased significantly on day 2 after the first vaccination compared with day 0."},
      {"type": "figure", "ref": "Figure 2A"}
    ]
  }
}
